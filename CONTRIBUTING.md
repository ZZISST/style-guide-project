# Как внести вклад в стайлгайд

## Как предложить изменение

1. Создайте ветку от `main`: `docs/<тема>` для текста, `ci/<тема>` для инфраструктуры.
2. Внесите изменения и проверьте их локально.
3. Сделайте коммит по Conventional Commits.
4. Откройте pull request в `main` и заполните шаблон.
5. Дождитесь ревью и прохождения CI.

## Conventional Commits

Формат заголовка коммита: `<тип>(<область>): <описание>`.

| Тип | Когда использовать |
| --- | --- |
| `docs` | Изменение текста документации |
| `ci` | Изменение CI и деплоя |
| `fix` | Исправление ошибки |
| `chore` | Служебные изменения |

Пример: `docs(accessibility): добавить правила доступности текста`.

## Процесс ревью

- Каждый PR проверяет хотя бы один участник, который не был автором.
- Ревьюер проверяет соответствие правилам стайлгайда и оставляет комментарии.
- Автор исправляет замечания отдельными коммитами.
- PR сливается в `main` после одобрения ревьюера и зелёного CI.

## Локальная сборка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
mkdocs serve
```

Проверка перед PR:

```bash
npx markdownlint-cli2 "**/*.md"
mkdocs build --strict
```

## Как добавить раздел

1. Создайте файл в `docs/`, например `docs/new-section.md`.
2. Начните файл с заголовка первого уровня.
3. Добавьте раздел в `nav` в `mkdocs.yml`.
4. Добавьте ссылку на раздел в `docs/index.md`.
